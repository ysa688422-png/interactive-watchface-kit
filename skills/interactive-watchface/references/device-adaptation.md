# 新设备或新版本的适配

以具体型号、系统版本和实际交付方式决定能力。未经验证的设备默认“待核实”，不能从品牌、屏幕相近或文件后缀相同推断兼容。

## 建立可追溯的能力记录

优先阅读项目已有 profile、厂商 SDK、官方开发文档、官方用户指南及已授权的格式工具。记录支持结论的来源与适用版本，至少区分：

| 项目 | 要确认的事实 |
| --- | --- |
| 显示 | 物理像素、逻辑坐标、圆角/圆屏遮挡、安全区、色彩与透明度 |
| 素材 | 支持的图片/动画编码、单资源与总包体限制 |
| 互动 | 点击热区、运行时/API、可读取数据、未知值定义和更新时间 |
| 生命周期 | 亮屏、熄屏、切换表盘、恢复时机及计时器约束 |
| AOD | 设备是否支持、独立布局/资源、打包标志、功耗限制 |
| 交付 | 格式、签名/身份要求、受支持的手机与导入渠道、所需工具许可 |

把“官方文档支持”“工具中已实现”“本地已校验”“真机已验证”分别标注；未知项保留未知。能力缺失时选择支持的子集并说明降级，不创建虚构 API、签名或安装包。

## 从现有适配扩展

1. 读取最接近的 profile 作为结构参考，复制到独立设备配置；不覆盖已验证配置。
2. 根据新设备证据更新显示、资源、交互、AOD 和安装字段，并列出尚未验证的差异。
3. 先用有权限的简单原创图形验证坐标、透明度、时间和一项互动，再接入人物素材。
4. 原生截图与独立格式验证通过后，按用户授权进行实机测试；记录实际设备与系统版本。

屏幕适配与运行时适配是两件事。单纯缩放照片不会得到新的原生 Lua 表盘；把原有包改后缀也不会实现跨设备兼容。

需要外部工具时核实许可、下载来源与平台要求。完整编译器未随仓库提供时明确说明依赖，保留工程供后续继续；不得用安装大量无关工具或更改系统配置来掩盖能力缺口。
